# AnimeTrack 全面检查与长期维护路线图

最后更新：2026-08-13

## 1. 文档目的

新功能已经基本稳定，后续维护重点转向安全、稳定性、模块化、无用代码清理、测试和文档。本路线图记录 2026 年 8 月全面检查的结果，作为后续逐项优化的长期清单。

默认工作方式：一次只处理一个主题，先完成静态检查、类型检查、自动化测试和独立生产构建，再执行 `npm run deploy:test`。涉及页面或交互时由用户自行验收，确认后创建 Git 提交并执行 `npm run deploy:prod`。

## 2. 项目约定与检查边界

- 动漫、漫画、观看历史、备注和统计数据均按“可以公开浏览”设计，匿名读取这些内容不作为隐私或越权问题。
- 管理员账号、密码哈希、`NEXTAUTH_SECRET`、AI Key 等仍属于敏感凭据，必须限制读取和传播。
- 写入、删除、导入、备份管理、AI 设置和资料补充等操作仍必须要求有效的管理员身份。
- 优化默认不改变现有页面外观、公开浏览方式和数据含义；确需改变时单独说明并验收。
- 不直接删除用途不明确的历史脚本，也不在没有备份和测试的情况下进行大范围重构。

## 6. 高优先级项目说明

### M-005 接口内部错误收敛

发现：部分 API 会把捕获到的 `error.message` 原样返回浏览器，例如数据管理、备份恢复、导入、漫画写入、AI 测试和时间线接口。数据库异常、磁盘路径或外部服务细节可能因此出现在响应中。

计划：

- 区分可安全展示的业务错误和仅供服务器排查的内部错误。
- 浏览器收到简短、稳定、容易理解的中文提示。
- 完整异常写入服务器日志，并附带不含敏感数据的请求上下文。
- 保留参数校验、资源不存在和权限错误的明确提示。

验收：

- 人为制造数据库、文件和外部请求失败时，响应不包含 SQL、绝对路径、密钥或调用栈。
- 服务器日志仍能定位具体失败环节。
- 现有前端错误提示和自动化测试正常。

### M-006 全量备份账号策略

发现：`npm run db:full-backup` 默认导出 `users` 表，其中包含管理员密码哈希。动漫数据允许公开，但密码哈希仍属于账号凭据。

计划：

- 默认全量 SQL 备份不包含 `users` 表。
- 只有显式传入参数时才导出账号，例如 `--include-users`。
- 在输出和文档中明显提示包含账号凭据的备份需要安全保存。
- 评估恢复脚本是否依赖当前默认行为，并补充兼容测试。

验收：

- 默认生成的 SQL 中不存在 `password_hash` 和 `users` 数据。
- 显式包含账号时仍可正确生成和恢复。
- JSON 便携备份继续不包含账号。

### M-007 日期真实性校验

发现：当前主要通过 `/^\d{4}-\d{2}-\d{2}$/` 检查格式，理论上会接受 `2026-02-31`、`2026-13-01` 等不存在的日期，也没有系统检查结束日期是否早于开始日期。

计划：

- 建立共享的真实日历日期校验方法。
- 动漫、漫画、备注、观看历史和导入数据使用同一规则。
- 对开始、首播、结束、发布日期制定明确的先后关系；允许确有需要的未知或不完整状态。
- 导入时给出具体作品和字段，方便修复数据。

验收：

- 闰年、月末、跨年等边界测试通过。
- 不存在日期和明显错误的日期关系被拒绝。
- 现有数据库中的合法数据可以正常导出、导入和编辑。

### M-008 Nginx 与入口安全配置

发现：应用构建和 PM2 启动已经脚本化，但域名入口处的 Nginx 配置、安全响应头、上传限制、代理超时和频率限制仍需系统复核并形成仓库内模板，避免迁移服务器后依赖人工记忆。

计划：

- 提供不包含真实域名和证书路径的 Nginx 示例配置。
- 明确 HTTPS、真实客户端 IP、WebSocket/流式响应、上传大小和超时设置。
- 为登录、AI、导入、备份恢复等高成本或敏感入口制定适度限流。
- 评估 CSP、`X-Content-Type-Options`、`Referrer-Policy` 等安全响应头，避免破坏现有远程封面显示。
- 增加配置检查和部署文档，不自动覆盖服务器现有配置。

验收：

- `nginx -t` 通过，现有页面、登录、AI 流式录入、上传和下载正常。
- HTTPS 和代理后的回调地址正确。
- 常规操作不受限流影响，明显的连续异常请求会被限制。

## 7. 中优先级项目说明

### M-009 依赖安全警告

当前生产依赖审计结果为 2 个中等风险，链路是 `exceljs` 间接依赖 `uuid`，没有高危或严重问题。

计划：优先评估兼容升级或上游修复，不使用会破坏依赖树的强制更新。若短期无法消除，应确认项目是否调用受影响的 `uuid` 缓冲区参数路径，并在文档中记录接受风险的理由和复查日期。

验收：升级后 Excel 导出测试、完整测试和生产构建通过；或形成有依据、带复查日期的暂缓记录。

### M-010 API 错误处理统一

计划建立共享的 API 错误类型和映射规则，统一处理：

- 参数错误：400；
- 未登录：401；
- 权限不足：403；
- 数据不存在：404；
- 数据冲突：409；
- 外部服务暂时失败：502 或 503；
- 未预期的内部错误：500。

这一项与 M-005 相关，但 M-005 先解决信息暴露风险，M-010 再做更大范围的结构统一。

### M-011 后端大型模块拆分

检查时较大的后端文件包括：

- `lib/anime.ts`：约 775 行；
- `lib/ai.ts`：约 637 行；
- `scripts/enrich/enrich_bangumi.js`：约 637 行；
- `lib/metadata/merge-policy.ts`：约 523 行；
- `lib/anime-import.ts`：约 522 行。

建议按职责拆分，而不是单纯按行数切割：

- 查询与写入仓储层；
- 数据映射和类型转换；

- AI 请求、响应解析和提示词；
- 元数据合并规则；
- 外部 Bangumi 服务适配。

每次只拆一个模块，要求行为测试先覆盖再移动代码，避免一次性大重构。

### M-013 历史脚本与重复代码清理

仓库中保留了封面迁移、远程封面修复、数据补充和旧导入导出脚本。后续应为每个脚本记录：当前入口、替代方案、是否仍需保留、最后验证时间。

处理规则：

- 仍有维护价值的脚本补充参数校验和文档。
- 被新功能替代但可能用于故障恢复的脚本移入归档目录，并标明只读用途。
- 确认没有调用方、没有恢复价值且 Git 历史可找回的脚本才删除。
- 重复的路径、日期、远程请求、备份和环境变量逻辑优先复用共享模块。

### M-014 关键流程测试补充

现有 144 项测试已经覆盖数据库迁移、导入、备份、时间线、封面安全和账号令牌等基础能力。仍需逐步补充：

- 管理员从登录到写接口的完整流程；
- 备份生成、下载、恢复和恢复失败后的状态；
- 导入过程中部分数据错误和事务回滚；
- 封面下载、生成缩略图和替换旧文件的完整流程；
- AI/Bangumi 超时、限流、无效响应和候选冲突；
- 主要写接口的未登录、旧令牌和非管理员场景；
- 日期和数据量边界。

### M-016 运行日志与监控整理

PM2 错误日志中存在外部扫描产生的无效 Server Action 请求等噪声。后续应区分真实应用错误、外部无效请求和可预期的外部服务失败，并考虑：

- 日志轮转和保留天数；
- 请求关联 ID；
- 健康检查失败告警；
- 备份任务失败告警；
- 对已知扫描噪声限流或降级记录。

不应简单隐藏所有错误，目标是让真正故障更容易被发现。

## 10. 单项完成标准

一项只有同时满足以下条件才标记完成：

1. 说明原来的行为、问题和修改后的行为。
2. 改动范围只属于当前主题，不夹带无关文件。
3. 为关键行为补充或更新自动化测试。
4. ESLint 和 TypeScript 检查通过。
5. 完整测试通过。
6. 独立生产构建通过。
7. `npm run deploy:test` 的候选健康检查和静态资源检查通过。
8. 涉及页面或交互时，用户完成实际验收。
9. 使用简短中文标题创建 Git 提交。
10. 需要正式发布时，在干净工作区执行 `npm run deploy:prod` 并确认生产健康检查通过。
