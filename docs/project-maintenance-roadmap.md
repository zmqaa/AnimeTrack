# AnimeTrack 全面检查与长期维护路线图

最后更新：2026-08-14

## 1. 文档目的

新功能已经基本稳定，后续维护重点转向安全、稳定性、模块化、无用代码清理、测试和文档。本路线图记录 2026 年 8 月全面检查的结果，作为后续逐项优化的长期清单。

默认工作方式：一次只处理一个主题，先完成静态检查、类型检查、自动化测试和独立生产构建，再执行 `npm run deploy:test`。涉及页面或交互时由用户自行验收，确认后创建 Git 提交并执行 `npm run deploy:prod`。

## 2. 项目约定与检查边界

- 动漫、漫画、观看历史、备注和统计数据均按“可以公开浏览”设计，匿名读取这些内容不作为隐私或越权问题。
- 管理员账号、密码哈希、`NEXTAUTH_SECRET`、AI Key 等仍属于敏感凭据，必须限制读取和传播。
- 写入、删除、导入、备份管理、AI 设置和资料补充等操作仍必须要求有效的管理员身份。
- 优化默认不改变现有页面外观、公开浏览方式和数据含义；确需改变时单独说明并验收。
- 不直接删除用途不明确的历史脚本，也不在没有备份和测试的情况下进行大范围重构。

## 6. 高优先级项目说明

### M-005 接口内部错误收敛

发现：部分 API 会把捕获到的 `error.message` 原样返回浏览器，例如数据管理、备份恢复、导入、漫画写入、AI 测试和时间线接口。数据库异常、磁盘路径或外部服务细节可能因此出现在响应中。

计划：

- 区分可安全展示的业务错误和仅供服务器排查的内部错误。
- 浏览器收到简短、稳定、容易理解的中文提示。
- 完整异常写入服务器日志，并附带不含敏感数据的请求上下文。
- 保留参数校验、资源不存在和权限错误的明确提示。

验收：

- 人为制造数据库、文件和外部请求失败时，响应不包含 SQL、绝对路径、密钥或调用栈。
- 服务器日志仍能定位具体失败环节。
- 现有前端错误提示和自动化测试正常。

### M-009 依赖安全警告

原问题：生产依赖审计报告 2 个中等风险，链路是 `exceljs@4.4.0` 间接依赖的 `uuid@8.3.2`。安全公告 [GHSA-w5hq-g745-h8pq](https://github.com/advisories/GHSA-w5hq-g745-h8pq) 说明，受影响行为是 `uuid.v3()`、`v5()` 和 `v6()` 对调用方提供的输出缓冲区缺少边界检查。

处理结果：ExcelJS 稳定最新版仍声明 `uuid ^8.3.0`，代码中只使用无参数的 `uuid.v4()`，没有受公告影响的调用。项目通过 npm `overrides` 将 ExcelJS 的间接依赖精确固定到首个修复版本 `uuid@11.1.1`；该版本保留 ExcelJS 所需的 CommonJS 和 `v4()` 接口，也已被项目中的 NextAuth 使用。安装后两处依赖复用同一版本，未使用会降级 ExcelJS 的 `npm audit fix --force`。

验收结果：`npm audit --omit=dev` 未发现已知漏洞，Excel 导出生成及重新读取测试通过。完整检查、独立生产构建和测试部署结果记录在本次交付中。

### M-010 API 错误处理统一

原问题：各路由直接传入数字状态码，错误体通常只有中文 `error`；未登录、失效令牌和权限不足统一返回 403，部分文件、导出、详情和备注路由的未预期异常还可能绕过共享日志与安全响应边界。

处理结果：新增共享错误类型、稳定错误码和 HTTP 状态映射，统一处理：

- 参数错误：400；
- 未登录：401；
- 权限不足：403；
- 数据不存在：404；
- 数据冲突：409；
- 外部服务暂时失败：502 或 503；
- 未预期的内部错误：500。

应用自有 JSON 错误现在固定包含 `{ error, code }`；前端 `ApiRequestError` 同时保留状态和错误码。未登录及账号失效使用 401，已登录但权限不足使用 403。路由共享边界负责将预期错误映射为稳定响应，并将未预期异常完整写入服务器日志；无效 JSON 统一为 400。完整约定见 [API 错误响应约定](./api-error-contract.md)。

验收：自动化测试覆盖错误码映射、401/403 分流、无效 JSON、外部服务错误、未预期异常日志和内部信息收敛；完整检查、独立生产构建和测试部署结果记录在本次交付中。

## 10. 单项完成标准

一项只有同时满足以下条件才标记完成：

1. 说明原来的行为、问题和修改后的行为。
2. 改动范围只属于当前主题，不夹带无关文件。

5. 完整测试通过。
